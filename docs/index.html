여기까지 완료 — 다음에 이어갈 기준

기본 탭과 탐색 개선 구현 완료. 탭 추가·전환·닫기에 이어 다른 사이트 링크의 새 탭 처리, 마우스를 올린 링크의 하단 표시, 탭 드래그 재정렬을 추가했다. 자동 검증과 최종 빌드를 완료했고, 사용자가 기존 창을 직접 닫은 후 새 실행 파일을 적용했다. 실제 마우스 드래그도 확인했다. 팝업 허용 선택은 다음 단계다.

  • 환경: Rust·Cargo·Visual Studio 빌드 환경 준비, WebView2 설치 확인, 예제 빌드·실행 성공.
  • 브라우저: 주소 입력, 이전·다음, 새로고침, 이동 기능 구현. 시작 화면은 새 탭에서 제공한다. 클릭한 웹 링크는 전체 호스트명이 같으면 현재 탭, 서브도메인을 포함해 다르면 새 탭에서 연다.
  • 광고 차단: adblock-rust + EasyList로 외부 광고 요청 차단 기본 ON. 게시자 HTML과 같은 사이트 콘텐츠는 유지하며 CSS 숨김은 사용하지 않는다.
  • 화면: PB 로고를 실행 파일·창·첫 화면에 적용했다. 탐색 버튼은 SVG만 표시하고, 하단 오른쪽에는 광고차단 ON / OFF만 표시한다. 누적 건수는 표시하지 않는다. 홈 버튼과 상단 제품명은 제거했다. 탭 누름 이동 효과를 제거하고 테두리 두께를 고정했다.
  • 목록 관리: 개발 원본은 filters/easylist.txt, 현재 실행 시에는 빌드에 포함된 목록을 사용한다. 외부 목록 우선 읽기와 자동 동기화는 아직 없다. 암호화·난독화는 하지 않기로 했다.
  • 검증: 단위 테스트 13개와 실제 WebView2의 로컬 광고 요청 차단·링크 이동·탭 처리·탐색 개선 검증, 빌드·코드 검사 통과. PB 화면 구성 확인 완료. 공개 사이트 전체의 광고 차단율을 측정한 것은 아니다.

다음에 할 한 가지: 다시 실행한 화면에서 탭을 누르거나 드래그할 때 세로 스크롤이 나타나지 않는지 사용자와 확인한다. 이후 자동 팝업을 보류하고 한 번 허용하거나 닫도록 안내하는 기능을 논의한다. 필터 보완·자동 갱신 등은 필요성을 논의한 뒤 별도로 진행한다.

이번 마무리에서는 관리 문서만 정리했다. 새 기능 구현·추가 설치·설정 변경은 진행하지 않았다.

01 · 프로젝트 방향

기본에 충실한 작고 가벼운 독립형 웹 브라우저를 만든다. 외부 광고 시스템의 무분별한 광고를 차단하고 웹 콘텐츠를 편하게 보는 경험이 핵심이다. 광고 차단의 실제 효과를 다른 기능 확장보다 먼저 확인한다.

확정한 내용

  • 제품 이름: Plain Browser
  • Rust를 중심으로 개발한다.
  • Windows용부터 개발하며, Rust + Wry + WebView2로 구성한다.
  • 외부 광고 시스템이 불러오는 광고 요청을 차단한다. 광고 제거를 제품의 핵심으로 우선 검증한다.
  • 게시자가 HTML에 직접 넣은 콘텐츠는 제거하지 않는다. 같은 사이트의 요청과 최상위 페이지 탐색도 보존한다.
  • 광고 요청 차단에는 adblock-rust와 EasyList를 사용한다. 화면 요소를 숨기는 기능은 적용하지 않는다.
  • 가볍고 작은 앱을 목표로 한다.

검토 중인 내용

  • 실제 사이트에서의 광고 차단 효과와 한국 사이트용 보완 필터 필요 여부
  • 필터 목록 갱신 방식과 사이트별 차단 예외 저장
  • 도메인에 따른 새 탭 이동과 팝업 허용 안내의 순차 구현
  • 본문 보기·별도 추적 차단·즐겨찾기·탭 복원 등을 추가할 시점
  • 지원 OS 세부 범위와 설치 용량·시작 시간·메모리 목표

첫 구현 범위는 주소창과 웹페이지 표시 영역을 갖춘 단일 창이다. 뒤로·앞으로·새로고침·시작 화면 이동을 함께 제공한다.

06 · 첫 실행 버전 0.1.0 — 초기 구현 기록

아래는 광고 차단을 넣기 전 첫 창의 기록이다. 현재 광고 차단 적용 상태는 다음 절을 참고한다.

사용자의 승인에 따라 프로젝트 루트에 브라우저 코드를 추가했다. 기존 env-check 예제는 유지했다. 브라우저 창·이벤트 처리는 Tao, 웹페이지 표시는 Wry와 설치된 WebView2 Runtime을 사용한다.

실행 방법

cd D:\Project\01_plainB
cargo run --locked

주소창에 example.com 또는 https://www.rust-lang.org 등을 입력하고 Enter 또는 이동 버튼을 누른다. 주소에 프로토콜이 없으면 HTTPS를 사용한다. 로컬 개발 주소 localhost:포트와 루프백 IP는 HTTP를 사용한다.

구현 범위와 한계

  • 주소창, 웹페이지 표시, 뒤로·앞으로 이동, 새로고침, 시작 화면 이동을 제공한다.
  • 최초 화면은 내장 안내 페이지이며 외부 사이트를 자동으로 열지 않는다.
  • 검색어 검색, 탭, 즐겨찾기, 광고 제거, 본문 보기는 아직 구현하지 않았다.
  • 새 창·팝업과 파일 다운로드는 지원하지 않으며 안내 문구를 표시한다.
  • 주소창은 HTTP·HTTPS만 받는다. 로컬 파일과 외부 앱 실행 프로토콜은 열지 않는다.
  • 웹 콘텐츠 영역에는 앱 명령을 실행하는 통신 기능을 연결하지 않았다.
  • 쿠키와 캐시 등 WebView2 데이터는 개발용 work/webview2 폴더에 저장한다. Edge 개인 프로필과 분리되며, 시크릿 모드는 아니다.
  • 설치 프로그램·기본 브라우저 등록·배포용 최적화는 이번 범위에 포함하지 않는다.

  • cargo build --locked 성공.
  • cargo test --locked 주소 처리 테스트 3개 통과.
  • cargo clippy --locked --all-targets -- -D warnings 통과.
  • 실제 창에서 내장 시작 화면과 입력한 HTTPS 페이지 표시 확인.
  • 뒤로·앞으로 이동 시 페이지와 주소창이 함께 갱신되는 것 확인.
  • 새로고침 후 페이지 유지, 최대화 시 주소창과 페이지 영역 크기 변경 확인.
  • 이동 버튼 줄바꿈을 수정한 최종 빌드의 화면 확인. 닫기 버튼으로 창이 종료되는 것 확인. 확인 후 창을 닫고 화면 제어를 마쳤다.

초기 실행에서 내장 HTML이 데이터 URL로 전달되면서 주소 제한에 걸리는 문제가 있었다. 내장 화면을 앱 내부 전용 주소로 제공하도록 바꿔 해결했다. 외부 데이터 URL을 일괄 허용하지 않는다.

직접 화면 확인 중 사용자가 제어 중임을 모르고 Esc를 눌러 중단한 일이 있었다. 이후 화면 제어 시작을 명시적으로 알리고 확인을 재개했다.

07 · adblock-rust 요청 차단 적용

상태: 기본 켜짐. 앱 실행 시 포함된 EasyList 네트워크 규칙으로 엔진을 준비하고, 웹페이지 리소스 요청을 WebView2에서 가로채 검사한다. 광고로 일치한 외부 요청은 빈 403 응답으로 대체하여 광고 원본 서버로 보내지 않는다.

사용 방법

cd D:\Project\01_plainB
cargo run --locked

창 하단 상태 표시줄의 왼쪽에는 로딩·완료·오류 안내, 오른쪽에는 광고차단 ON / OFF만 표시한다. 누적 건수는 표시하지 않으며, 개별 차단이 발생할 때마다 화면을 갱신하던 알림도 제거했다. 버튼을 누르면 차단을 켜거나 끄고 현재 페이지를 다시 연다. 다시 실행하면 기본 ON으로 돌아온다.

최종 버튼 디자인: 이전·다음·새로고침·홈·이동은 굵은 선의 SVG 아이콘만 표시한다. 화면의 글자는 모두 제거했으며, 마우스를 올리면 기능 이름을 표시하고 접근성 이름을 유지한다. 새로고침은 로딩 중에도 SVG를 유지한다.

PB 브랜드 아이콘: 초록색 둥근 사각형 안에 P와 B를 형상화했다. 첫 화면의 기존 소문자 p를 대체하고 창·실행 파일 아이콘에도 적용했다. 원본은 assets/plain-browser.svg, Windows 아이콘은 16~256px 크기를 포함한 assets/plain-browser.ico이다. tools/generate-icon.ps1로 PNG·RGBA·ICO를 재생성할 수 있다. 빌드용 winresource를 추가했으며 별도 시스템 프로그램은 설치하지 않았다.

PB 아이콘 및 버튼 변경은 빌드와 실제 창에서 확인했다. 확인 후 창을 열어 두었으며 광고차단은 ON이다.

화면 구성 변경: 상단에는 주소창과 탐색 버튼만 두고, 기존 상태 메시지와 광고 차단 정보는 높이 30px의 하단 상태 표시줄로 옮겼다. 웹페이지는 상단 60px과 하단 30px 사이에 표시하며 창 크기 변경 시 함께 조정한다. 기존 두 개의 WebView를 유지한다.

하단 표시줄의 메시지 배치와 ON/OFF 버튼 동작을 실제 창에서 확인했다. 최초에는 차단 건수도 표시했으나, 사용자가 불필요하다고 판단하여 제거했다.

원본: EasyList · 버전 202611131402 · filters/easylist.txt에 원본을 포함했다. 네트워크 규칙만 읽는다. 출처·해시·라이선스는 filters/NOTICE.txt와 동봉된 라이선스 파일에 기록했다.

  • 같은 사이트에서 전달하는 광고는 의도적으로 남길 수 있다.
  • 외부 광고 요청이 처음 HTML에 선언됐는지, JS가 나중에 만들었는지로 구분하지는 않는다. 둘 다 외부 광고 시스템 요청이면 대상이다.

  • 요청 오류 시 허용되는 경우가 있으며, 오류 안내를 표시한다. 필터 연결 자체가 실패하면 활성화된 것처럼 앱을 시작하지 않는다.

문제: 기존 코드는 새 창 요청을 일괄 거절하여 target="_blank" 링크와 클릭으로 실행되는 window.open() 링크가 이동하지 않았다.

09 · 2026년 11월 14일 — 기본 탭 처리

이번 범위: 기본 탭 표시줄·추가·전환·닫기만 구현했다. 도메인 자동 분기와 팝업 허용 안내는 아직 적용하지 않았다.

  • 상단 탭 표시줄의 ＋를 누르면 새 시작 탭을 만들고 전환한다.
  • 탭 제목을 누르면 해당 페이지로 전환한다. 주소창·앞뒤 이동·로딩 안내·창 제목도 해당 탭에 맞게 바뀐다.
  • 탭마다 페이지·제목·입력 내용·방문 기록을 유지한다. 백그라운드 탭에서 온 제목이나 로딩 이벤트는 해당 탭에만 반영한다.
  • 탭의 ×로 닫는다. 현재 탭을 닫으면 오른쪽 탭, 오른쪽이 없으면 왼쪽 탭을 선택한다. 다른 탭을 닫아도 현재 탭은 유지한다.
  • 마지막 탭을 닫으면 새 시작 탭을 하나 남긴다. 닫힌 페이지의 요청·링크 핸들러와 WebView를 정리한다.
  • 탭이 많으면 표시줄을 가로로 스크롤할 수 있다. 탭 표시줄에 키보드 초점이 있을 때 좌우 화살표·Home·End로 선택할 수 있다.
  • 광고 필터 엔진과 사용자 프로필은 공유하고 각 탭에 광고 요청 차단을 연결한다. ON/OFF는 앱 전체 설정이며 토글 시 현재 탭을 새로고침한다.
  • 기존처럼 사용자가 클릭한 새 창 대상 링크는 해당 원본 탭에서 열고, 자동 팝업은 차단 안내만 표시한다.

검증: 단위 테스트 11개 통과, 실행 파일 빌드·코드 검사·형식 검사 통과. 실제 브라우저 코드와 로컬 UI 통신을 사용하는 숨겨진 WebView2 검증에서 탭 추가·전환·배경 탭 닫기·마지막 탭 대체, 입력 내용 보존, 개별 방문 기록, 주소창 동기화, 창 크기 변경을 확인했다. 새 앱 창에서 탭 표시줄의 실제 배치도 확인했다.

기본 탭 구현 당시 미지원: 다른 도메인 링크의 자동 새 탭 처리와 탭 순서 변경은 다음 절에서 추가했다. 팝업 허용 선택, 탭 세션 저장·복원, 자동 절전은 아직 없다. 숨긴 탭도 메모리와 페이지 실행 상태를 유지한다.

하단 링크 주소 표시

현재 탭의 링크에 마우스를 올리면 하단 왼쪽에 대상 주소를 표시하고, 벗어나면 로딩·완료 안내로 돌아간다. 주소가 길면 줄임표로 표시하며 전체 주소는 해당 영역의 툴팁으로 확인한다. WebView2의 기본 상태 변경 이벤트를 사용하며, 웹페이지에 앱 제어 명령을 보내는 기능을 추가하지 않았다.

도메인에 따른 이동

  • 같은 전체 호스트명의 클릭 링크는 현재 탭에서 연다. 경로·포트·HTTP/HTTPS 차이는 새 탭 기준에 포함하지 않는다.

  • 주소창 직접 입력, 뒤로·앞으로, 새로고침, 현재 탐색의 리디렉션은 현재 탭을 유지한다.
  • 전체 호스트명으로 비교한다. 대소문자와 끝의 점은 정규화하며 서로 다른 IP 주소도 구분한다.
  • 자동 팝업은 기존처럼 차단하며 이번에는 허용 선택 UI를 추가하지 않았다.

마우스로 탭 순서 변경

탭 제목 부분을 누른 채 좌우로 끌면 순서를 미리 보여주고, 놓을 때 순서를 적용한다. 양쪽 가장자리에서 가로 스크롤을 지원한다. 드래그해도 선택한 탭·페이지·방문 기록은 바뀌지 않는다. 닫기 버튼은 드래그 대상에서 제외한다. 순서는 현재 실행 중에만 유지한다.
